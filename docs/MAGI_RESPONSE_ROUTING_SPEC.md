# MAGI RESPONSE ROUTING SPECIFICATION

Status: CORE / CANONICAL
Purpose: MAGI Webが質問内容に応じて、不要な三賢人審議を避け、最適な回答方式を自動選択するための基準仕様。

## Core principle
MAGIは「何でも三賢人で審議するシステム」ではない。
必要なときだけ三賢人を招集する。
普段の事実確認は速く簡潔に、専門判断は適切な賢人一人で、複数の価値・専門領域が衝突する重要判断だけ正式審議にする。

ユーザーに毎回モードを選ばせない。質問を受けたMAGI側が自動で振り分ける。

---

## MODE 1 — DATA RESPONSE
対象: 単純な事実・記録・数値の確認。

例:
- 「○○の最近の打撃成績は？」
- 「大久保の最近6試合の打率は？」
- 「橋向の防御率は？」
- 「三国中との対戦成績は？」

動作:
- Google Drive等の確認済みデータを検索する。
- 三賢人は招集しない。
- 数字、対象期間、母数、参照元を簡潔に示す。
- データが無い場合は推測せず「確認できない」と答える。

UI:
DATA RESPONSEとして軽量表示。三賢人の顔・投票・相互検証は出さない。
必要なら小さく「事実確認のため三賢人審議は行っていません」と示す。

---

## MODE 2 — SPECIALIST RESPONSE
対象: 一つの専門領域で十分に答えられる分析・助言。

MELCHIOR-1 / VERIFY:
- 「最近○○の打撃は上向いている？」
- 「この数字は信用できる？」
- データ分析、比較、記録検証。

BALTHASAR-2 / DECIDE:
- 「この場面なら送りバント？」
- 「この継投はどう？」
- 明確に戦術領域だけで処理できる相談。

CASPER-3 / EVOLVE:
- 「控えの1年生をどう育てる？」
- 「この役割の持たせ方はどう？」
- 明確に育成・役割・組織領域だけで処理できる相談。

動作:
- 担当賢人一人だけが回答する。
- 一人称・人格・価値観・パーソナルカラーは `MAGI_THREE_WISE_MEN_BRAND.md` に従う。
- 他領域の重大な論点が発生した場合は、無理に一人で答えず THREE WISE MEN DELIBERATION へ昇格できる。

---

## MODE 3 — THREE WISE MEN DELIBERATION
対象: 複数の価値、専門領域、リスクが衝突する意思決定。

例:
- 「大久保を1番で固定すべき？」
- 「主力中心で固定するか、全員の育成と競争を優先するか？」
- 「勝つためにこの選手を連投させるべき？」

動作:
- MELCHIOR、BALTHASAR、CASPERを正式招集する。
- CASE → EVIDENCE → INDEPENDENT JUDGMENT → REVEAL → CROSS EXAMINATION → SECOND JUDGMENT → FINAL DECISION を基本とする。
- 三人を無理に対立させない。同じ結論でも理由の違いを保持する。
- 少数意見と未解決警告を消さない。

UI:
LINE風の「MAGI 公開審議」を使用し、三賢人が互いの意見に反応していることが分かる表示を優先する。

---

## Routing authority / MAGI CONTROL
MAGI CONTROLは三賢人とは別の第四人格ではない。
ユーザーに意見を述べる存在でもない。

役割:
- 質問を受け取る。
- DATA RESPONSE / SPECIALIST RESPONSE / THREE WISE MEN DELIBERATION のどれが適切か判定する。
- 正式審議では一次判定の開示、相互検証、二次判定、最終集約を進行する。
- 三賢人の独立性を守り、勝手な第四意見や妥協案を作らない。

MAGI CONTROLは原則として裏方の制御層とする。UI上で名称を前面に押し出す必要はない。
ユーザー向けには必要に応じて「三賢人審議を開始します」「データ回答」等の自然な表示を使う。

---

## Escalation rule
最初の分類は固定ではない。
DATA RESPONSEで取得した事実から判断問題が生じた場合、ユーザーの質問意図に応じてSPECIALISTまたは正式審議へ進める。
SPECIALISTが自分の専門領域だけでは責任ある回答ができないと判断した場合、正式審議へ昇格する。

ただし、単純な数値質問を勝手に大規模審議へ拡張しない。

---

## Product principle
普段は速く、必要なときだけ深く。
三賢人が登場すること自体に意味と重みを持たせる。

MAGIの理想は、
「何を聞いても大げさなAI」ではなく、
「質問の重さを理解し、必要なだけ考えるシステム」
である。
