# MAGI-WEB CORE REBUILD — 2026-09-09

## 目的を固定する

MAGI-WEBの目的は「ルーターを正しく分類すること」でも「テストを全部PASSさせること」でも「1秒で返すこと」でもない。

目的は次の3点だけ。

1. **人間の自然な質問の意味を理解する。**
2. **その質問に答えるために必要な情報をMAGI自身が探して取得する。**
3. **取得した根拠だけを使い、質問そのものへ的確に回答・審議する。**

固定原則：

> 人間がMAGIの聞き方に合わせるのではなく、MAGIが人間の聞き方を理解する。

---

## 正式な一本の処理順

今後の本番経路は、必ず次の順序を守る。

**QUESTION → UNDERSTAND → EVIDENCE PLAN → RETRIEVE → VERIFY → ANSWER / DELIBERATE**

### QUESTION
ユーザーが普段の日本語で質問する。専用コマンドや決められた言い方を要求しない。

### UNDERSTAND
質問の対象・目的・期間・判断依頼か事実照会かを理解する。ルート名は内部処理であり目的ではない。

### EVIDENCE PLAN
「この質問へ答えるには何が必要か」を決める。
例：
- OPS質問 → 当該年度のXLSM正本
- 盗塁や守備詳細 → XLSM照合済みCSV
- 「希望ポジション一覧を見て審議」→ 希望ポジション一覧そのもの
- 起用判断 → 成績だけでなく、質問内容に応じて役割・守備・過去実績等

### RETRIEVE
MAGI自身がDrive等から必要資料を探して取得する。ユーザーに既知のファイルIDや完全なファイル名を言い直させない。

### VERIFY
取得した資料が本当に質問の根拠として使えるか確認する。
- 成績はXLSM正本優先
- CSVは照合済み範囲だけ
- 資料候補が複数で本当に一意でない時だけ確認質問
- 矛盾は黙って混ぜない

### ANSWER / DELIBERATE
- 事実照会は根拠から直接回答
- 判断依頼は取得したEvidenceをそのまま正式3賢人へ渡す
- 3賢人は同じEvidenceを使いながら独立判断する

## 残すもの

以下は目的を支える部品として継続使用する。

- 正式質問理解ルーター
- XLSM正本の決定論的読取
- XLSM ↔ CSV整合性ゲート
- 旧チームFULL OPEN済み詳細データ
- 正式3賢人エンジン（PRIMARY → CROSS → SECOND → FINAL）
- Google Driveサービスアカウントの読み取り専用取得
- LINEログイン・利用者管理
- 正式ロスターと選手名正規化

## 権限を下げるもの

以下は削除対象ではないが、**本番の最終判断を決める権限を持たせない**。

- ブラウザ内の旧 `routeQuestion()` キーワード判定
- ブラウザ内の旧 `analyze()` / 簡易melchior / balthasar / casper
- キーワード一致だけの `searchDataEvidence()`
- 速度だけを目的としたprewarm
- 特定質問だけを通す例外ハードコード

これらは互換・表示・非常時fallbackとして残してもよいが、COREの上位には置かない。

---

## 新COREの責務

本番の「MAGI実行」は `api/magi/core.js` を入口とする。

COREは以下を決める。

- 質問の意味
- 必要Evidence
- Evidenceの取得結果
- 事実回答か正式審議か

資料参照型審議では、COREが資料を特定して本文をEvidence Packetへ変換し、そのEvidence Packetを正式3賢人へ渡す。

最初の対象として、XLSX / XLSM / XLS / CSV / TXT / MD / JSON / Google Sheet / Google Docを扱う。PDF等、本文を安全に読めない形式は読めたふりをしない。

## 基準テスト

今後は個別ルートのPASS数より、次の実利用テストを優先する。

### A. 事実照会
「陽翔の今期OPS教えて」
- 大久保 陽翔を理解
- 今期を理解
- XLSM正本を選択
- .912を返す

### B. 資料参照審議
「希望ポジション一覧の内容を見て、チームの守備配置で気になる点を審議して」
- `希望ポジション一覧（2026年7月）.xlsx` を自動特定
- 内容を読む
- その内容をEvidenceとして3賢人へ渡す
- CLARIFYでファイル名を聞き返さない

### C. 曖昧な依頼
「レポート見せて」
- 本当に対象が複数なら1回だけ確認
- 勝手に資料を決めない

### D. 判断依頼
「大野 竜暉をクローザー固定すべき？」
- 数値を返すだけで終わらない
- 必要Evidenceを集める
- 正式3賢人審議へ進む

## 開発ルール

1. 新しい修正は上の3目的のどれを改善するか説明できなければ入れない。
2. 速度改善は正確性とEvidence取得が完成した後。
3. テストの期待値にコードを合わせるのではなく、実際の質問意図にテストを合わせる。
4. 例外ハードコードより一般規則を優先する。
5. 「ルートが合った」だけでは合格にしない。最終回答まで正しくて合格。
6. Driveに必要資料があるなら、MAGIが探す。ユーザーに探させない。
7. 読めていない資料を読んだふりしない。
8. 数値を作らない。

## 今回の立て直しで行う変更

- 速度用 `prewarm-stats` API枠を廃止し、目的中心の `api/magi/core.js` に置き換える。
- `api/magi/_evidence-resolver.js` を追加し、質問から必要資料を自動特定・読取する。
- メイン「MAGI実行」はCOREを最初に呼ぶ。
- COREが `DELIBERATION` と判断した場合、取得済みEvidenceを正式 `MAGI_ENGINE_V1` に直接渡す。
- 旧ブラウザ内キーワードEvidenceはCOREでEvidenceを取得できなかった案件のfallbackへ降格する。
- prewarmは停止する。速度は目的達成後に再評価する。

この文書を今後のMAGI-WEB改修の優先基準とする。
