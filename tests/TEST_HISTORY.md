### 複数ターン会話テスト — Run C

- 実行日時: **2026-09-08 20:41 JST 頃**
- シナリオ数: 30
- 結果: **27 PASS / 3 FAIL / API ERROR 0**
- ブラウザ画面上で確認できたFAIL: **M13 / M19**
- 3件目のFAIL: **共有スクリーンショット内では未特定。推測で記録しない。**
- routerVersion: **画面に当時表示欄がなく、実行結果からの直接記録はできていない。テストAPIはこの時点で正式入口 `_question-router-current.js` を使用。**

M13 領域確定後に期間訂正:

1. 「竜暉の成績見たい」 → `CLARIFY`
2. 「投手」 → `PITCHING_LOOKUP`
3. 「今季じゃなくて通算で」

期待:
- 3ターン目: `PITCHING_LOOKUP / CAREER`

実際:
- 3ターン目: `DELIBERATION / HIGH / safe=true`

M19 確認後に期間追加:

1. 「陽翔の成績」 → `CLARIFY`
2. 「投手で」 → `PITCHING_LOOKUP`
3. 「それの通算」

期待:
- 3ターン目: `PITCHING_LOOKUP / CAREER`

実際:
- 3ターン目: `DELIBERATION / HIGH / safe=true`

共通原因:
- 「通算で」「それの通算」「今季じゃなくて通算で」のような**期間だけを追加・訂正する短い返答**を、直前の照会の継続ではなく新しい判断依頼として誤解する場合があった。
- これはM13/M19固有の文言問題ではなく、会話文脈における `対象 + 領域 + 期間` の継承問題として扱う。

修正:
- 正式入口を **`v10-context-scope-guard`** に更新。
- 期間だけの追加入力・訂正では、直前までに確定した選手と打撃/投手領域を保持する。
- `通算 / 今季 / 前シーズン / 最近 / 直近6試合 / YYYY-YYYY` を期間変更として解釈する。
- 「今季じゃなくて通算で」のように複数の期間語がある場合は、文中で最後に明示された期間を最新訂正として採用する。
- 期間だけの変更で `DELIBERATION` に切り替えない。
- この一般修正はM13/M19だけでなく、M21/M29等の期間往復の回帰保護も目的とする。

## ルーター経路整理

M27対応中、一時的に `api/magi/_question-router-v2.js` を修正したが、実際のブラウザテスト経路は別だった。

この事故を再発させないため、正式入口を新設した。

2026-09-08 現在:

- 正式入口: **`api/magi/_question-router-current.js`**
- 基礎ルーター: `api/magi/_question-router.js`
- 会話補助: `api/magi/_conversation-recovery.js`
- `api/magi/health.js` は正式入口 `_question-router-current.js` を使用
- current test routerVersion: **`v10-context-scope-guard`**

`api/magi/_question-router-v2.js` は現在のブラウザテスト経路の正本ではない。

### v9-understanding-guard で追加した一般ガード

M11専用・M14専用の固有文言ベタ書きではなく、次の一般原則を追加した。

1. **比較軸のない「AとBどっちがいい？」**
   - 打撃・投手・守備・起用目的等が明示されていなければCLARIFY
   - 「どっちを4番」「どっちが先発向き」のように目的が明確なら判断へ進める

2. **曖昧な「成績」質問で人物だけを選び直した場合**
   - 人物が確定しても、打撃/投手が未確定ならCLARIFY継続
   - 人物を選んだだけでDELIBERATIONへ飛ばさない

### v10-context-scope-guard で追加した一般ガード

3. **期間だけの追加・訂正を照会継続として扱う**
   - 直前に選手と打撃/投手領域が確定している場合、期間だけの短い返答は同じLOOKUPを継続
   - 最新の明示期間を優先
   - 期間変更だけを理由にDELIBERATIONへ進めない
